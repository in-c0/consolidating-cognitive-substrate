Programme-vocabulary correction from the owner review on
[umbrella issue #1](https://github.com/in-c0/consolidating-cognitive-substrate/issues/1).
Pre-result and pre-scaffold: applied **before** `adaptive-commitment` is created,
so that repository is not born under the wrong programme contract.

No sibling repository was read for state changes and none was modified. This is a
vocabulary and ledger correction, not a reconciliation of remote state; the
2026-09-02 live reconciliation remains current for repository status.

## The error being corrected

The umbrella used one word — **COMMIT** — for two different decisions:

| | Decision | Track |
|---|---|---|
| **COMMIT_INTERNAL** | making information or state durable in the substrate | `state-promotion` |
| **COMMIT_EXTERNAL** | releasing cognition outward: `WAIT` / `THINK` / `ASK` / `RESPOND` / `ACT` | `adaptive-commitment` |

This was not a shorthand. Using one word **presupposed that a single mechanism
governs both**, which is a research hypothesis with a low prior — the two domains
differ in reversibility, in cost structure, and in who bears the consequence.

Two concrete harms had already followed:

1. **`adaptive-commitment` was mischaracterised.** The umbrella recorded it as a
   refinement of `state-promotion`'s memory-consolidation threshold. It is not,
   and never was; it is the outward/behavioural commitment track, deliberately
   scoped as a separate domain. The error was the umbrella's, produced by its own
   overloaded vocabulary.
2. **A `plasticity-routing` divergence was misdiagnosed.** On 2026-09-02 the
   umbrella recorded that track's refusal to call its `SLOW` write a "commitment"
   as an unresolved conflict. Under the split it is not a conflict at all: that
   track was using COMMIT_EXTERNAL's meaning and was right to decline. **No
   sibling needed to change anything, and none was asked to.**

## Changes

### Vocabulary

`COMMIT` is retired as an operator. `tools/validate_ledger.py` rejects it in
`ledger/dag.json` with a message pointing at CCS-C12, so the distinction cannot
erode back by habit. All eight previously-`COMMIT` DAG nodes are now
`COMMIT_INTERNAL`; `adaptive-commitment/EXP-A1` is `COMMIT_EXTERNAL`.

Every claim now carries a `domain` field, rendered as a column in the claim
ledger.

### CCS-C12 — new, `theoretical-conjecture`

The unification hypothesis, given an explicit falsifiable home rather than being
assumed by the vocabulary:

> One learned mechanism, given the appropriate evidence and cost structure, can
> govern both when state is made durable and when an outward response is
> released, at least as well as two domain-specific mechanisms at matched total
> budget.

Four falsifiers, the last of which the old vocabulary was hiding:

1. The two decisions depend on disjoint evidence.
2. A shared mechanism underperforms two separate ones at matched budget.
3. Optimal timing in one domain is uncorrelated with the other.
4. **The cost structures are incommensurable** — an internal write costs
   parameters and interference, an external action costs latency and consequence
   — so no single objective expresses both without an arbitrary exchange rate.

Falsifier 4 can hold even if a shared mechanism turns out to be buildable. It is a
way for the claim to be false on *measurement* grounds, and it is the reason the
resource envelope below is a precondition rather than a convenience.

Implementation is `none` and will stay there: `state-promotion` implements
COMMIT_INTERNAL only, `adaptive-commitment` does not exist, and **no track
implements both**, so no track can currently test unification.

### CCS-C5 — re-scoped, not promoted

The "adaptive consolidation threshold beats fixed threshold" idea is retained as a
**`state-promotion` COMMIT_INTERNAL follow-on** and detached from
`adaptive-commitment`. Status stays `theoretical-conjecture`, implementation stays
`none`.

Its mapped experiment is `state-promotion/EXP-F1`, which is flagged in the DAG as
an **umbrella-side candidate, not that track's roadmap**. `state-promotion` has
not adopted an adaptive-threshold follow-on. If it declines, the correct action is
to retire CCS-C5, not to reassign it a second time.

### CCS-C1 — restated

The decomposition is now explicitly the **state** pipeline and terminates in
COMMIT_INTERNAL. Where COMMIT_EXTERNAL attaches — inside the pipeline, alongside
it, or under a shared principle — is unresolved and tracked as CCS-C12.

A third falsifier was added, from an ambiguity the COMMIT split made visible:

> ACCUMULATE is read here as *"retain candidate experience"* and by
> `plasticity-routing` as *"continue gathering / thinking"*. Those are not
> obviously the same operator, and the second reading sits closer to
> COMMIT_EXTERNAL's `WAIT`/`THINK` than to state retention.

**ACCUMULATE has deliberately not been split.** No track has operationalised
either reading, and splitting it now would be inventing structure ahead of
evidence — the same error as writing a behavioural-commitment claim before
`adaptive-commitment` defines one.

### `adaptive-commitment` — role corrected before scaffolding

- Role rewritten to COMMIT_EXTERNAL, with the `WAIT`/`THINK`/`ASK`/`RESPOND`/`ACT`
  action space and its accuracy/latency/intervention/consequence trade-offs.
- Component renamed `commit-policy` → `external-commitment-policy`.
- **Owns no CCS claim**, by owner decision. A behavioural-commitment-timing claim
  is to be written only after that track's own literature audit and
  preregistration define its exact falsifiable form.
- **`blocked_by` cleared.** It is not gated on `state-promotion/EXP-001`; it was
  scoped as a separate domain. It is now the one track that could produce the
  programme's first admissible result without the state pipeline reading out.

### Resource envelope — now a formal precondition

New: [`ledger/resource_envelope.json`](../../ledger/resource_envelope.json) and
[RESOURCE-ENVELOPE.md](../RESOURCE-ENVELOPE.md).

Twelve dimensions covering stored and active parameter capacity, write
operations, training/inference/decision/consolidation compute, storage bytes,
evidence reads, wall runtime, and — new with COMMIT_EXTERNAL — latency to response
and intervention cost.

Native per-track units remain **authoritative**; this is a reporting layer, not a
replacement, and no track is asked to change its internal accounting.

Current coverage: **18 of 60 track/dimension cells mapped, 2 incommensurable.**
Both incommensurable cells belong to `adaptive-commitment` — latency and
intervention cost have no counterpart in any other track.

Three enforced invariants:

- every track must classify **every** dimension as `mapped`, `unmapped` or
  `incommensurable`; an undeclared dimension is an unexamined one;
- a non-additive dimension must say why, so an integration total cannot quietly
  sum it;
- while any `incommensurable` dimension is open, `ccs/EXP-I1` and `ccs/EXP-U1`
  may not leave `not-designed`.

That last one makes the owner's pre-integration prerequisite mechanical rather
than advisory: **"matched total budget" has no referent today**, so the primary
comparison of both CCS-C8 and CCS-C12 cannot be stated, let alone run.

Three open problems are recorded, of which OP-3 is that **nobody owns the
envelope**. Populating it is umbrella work; reconciling a genuine cross-track
disagreement about a dimension's meaning is not something the umbrella can direct.
